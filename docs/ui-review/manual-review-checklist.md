# UI 人工评审清单（自动化无法替代的部分）

> 自动化几何测试只证明布局规则没有破坏，不能替代以下审美与真实使用评审。
> 评审时每项记录“通过 / 修改 / 暂缓”，审美偏好确认后再沉淀为设计令牌或几何规则。

## 1. 玻璃与视觉层次

- [ ] 首页余额栏、卡片、底部导航、设置页卡片和按钮的玻璃材质是否统一。
- [ ] 默认光斑与自定义图片背景下，玻璃边缘是否清晰但不过度折射。
- [ ] 深色模式下蒙层是否既能保留玻璃感，又能保证正文可读。
- [ ] 卡片之间、面板与页面之间的层级是否清楚，没有“整页一块白板”的感觉。

## 2. 留白与信息密度

- [ ] 首页空态、成功态、错误态的视觉重心是否稳定。
- [ ] 设置页长列表的分组间距是否容易扫读，是否有过密或过空区域。
- [ ] 实验室展开/收起时，预览和调参的优先级是否符合使用习惯。
- [ ] 字体放大到 1.3 后，文字行距和卡片高度是否仍舒适。

## 3. 可读性与配色

- [ ] 正文、次要文字、数值和标签在浅色/深色背景上是否清晰。
- [ ] 玻璃背景最亮和最暗区域的文字是否都可读。
- [ ] 同类按钮颜色、字重、字号是否统一，主操作是否足够突出。
- [ ] 错误、警告、余额不足等状态色是否具有一致语义。

## 4. 动效与操作手感

- [ ] 底部导航拖动、吸附和按压过程中，图标与选中胶囊是否始终对齐。
- [ ] 滑块拖动与页面滚动是否互相干扰。
- [ ] 下拉刷新、展开/收起、页面切换的动画是否连续且不过度。
- [ ] 低性能或长时间滚动后是否出现明显掉帧、错位或残影。

## 5. 真实使用边界

- [ ] 有真实余额、无数据、网络失败、鉴权失败、网页令牌失效时，卡片内容是否稳定。
- [ ] 长模型名、长 Key 名称、大金额和多行错误信息是否仍可读。
- [ ] 横屏、小屏、长屏、系统字体放大后，关键操作是否都能到达。
- [ ] 小组件与 App 内余额信息是否使用一致的数据口径和状态表达。

## 6. 评审后的规则沉淀

- 若某一项被确认为长期偏好，应写入 `baseline.md`，并补充对应的静态或几何断言。
- 若只是单次审美取舍，不改变现有令牌，但需记录原因，避免后续重复摇摆。
