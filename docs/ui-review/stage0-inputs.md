# 阶段 0：UI 协调性评审输入清单（草案）

> 状态：草案，待评审。本清单只定义输入与判定规则，**不要求立即修改界面代码**。
> 目标：让"无基线审计"与"有基线门禁"两种模式都有明确、可复现的输入。

## 1. 两种运行模式

| 模式 | 用途 | 需要的输入 | 允许的结论 |
| --- | --- | --- | --- |
| 审计模式（audit） | 摸清现状、形成事实清单 | 源码；页面清单 | 只输出事实与差异，不判缺陷 |
| 门禁模式（gate） | 改动验收、防止回退 | 本清单全部 + 已确认令牌与阈值 | 按 P0/P1/P2 判定通过与否 |

## 2. 可测性标签（testTag）规范（待添加，不在本轮实施）

- 命名规则：`页面:容器:元素`，全小写英文，例如：
  - `home:balanceCard:root`、`home:usageCard:root`
  - `settings:glassLab:enterButton`
  - `lab:preview:topBar`、`lab:preview:balanceCard`、`lab:preview:sampleButton`
  - `lab:panel:root`、`lab:panel:expandButton`、`lab:panel:slider:cornerRadius`
  - `nav:bottom:item:home`、`nav:bottom:item:settings`
- 自绘玻璃组件（`LiquidCard` / `LiquidButton` / `LiquidSlider` / `BottomTabs`）需要在**外层容器**打标签；只依赖合并语义树会丢失内部结构。
- 标签只描述"角色"，不描述位置，避免布局调整后失效。

## 3. 页面进入路径与前置状态

| 页面 | 进入路径 | 前置状态 |
| --- | --- | --- |
| 首页 | 冷启动 | 分别覆盖：未配置、已配置且有数据、加载中、请求失败 |
| 设置页 | 首页底部导航"设置" | 同上，另覆盖已填/未填 API Key 与网页令牌 |
| 玻璃效果实验室 | 设置 → 全局液态玻璃效果 → 进入玻璃效果实验室 | 展开与收起两种稳定态 |
| WebLogin | 设置 → 网页一键登录 | 仅审查布局骨架，不做真实登录 |
| 检查更新 / 下载弹窗 | 设置 → 关于 | fake 更新信息，不访问真实网络 |

## 4. 测试数据（fake，禁止真实凭证）

- `BalanceResponse`：总额 123.45、granted 100.00、toppedUp 23.45。
- 用量数据：累计消费、请求数、Tokens、按模型/按 Key 各 2 条。
- 错误态：网络失败、鉴权失败（401）。
- 明确禁止把真实 API Key、`userToken`、登录 Cookie 写入测试或报告。

## 5. 状态与设备矩阵

- 核心页面（首页、设置、实验室、底部导航）：
  状态（空/加载/成功/错误）× 主题（浅色/深色）× fontScale（1.0 / 1.3）。
- 次要页面与弹窗：成功态 × 浅色 × fontScale 1.0。
- 设备（**一律用 dp，不用物理像素**）：
  - 360×640dp（小屏）
  - 360×800dp（常见）
  - 411×891dp（大屏）
  - 360×800dp @560dpi（本机 vivo 长屏等效：1260×2800px）
- 仅几何与排版；折射、模糊、色散不进矩阵，由人工评审。

## 6. 测量环境固定项

1. 只测稳定态：展开/切换动画结束，拖动动画不在测量中。
2. `waitForIdle()`；异步数据用 fake，超时记 `blocked`。
3. 固定语言 zh-CN、固定默认光斑背景（自定义背景图单独一组）。
4. 坐标统一为**内容区坐标**（去除状态栏/导航栏/手势条 Insets）。
5. 几何量化优先 instrumentation；Robolectric 只作可选加速，失败即降级为 `blocked`，不算产品缺陷。

## 7. 报告契约（输出格式）

机器可读 JSON + 人读摘要。单条记录字段：

```json
{
  "page": "lab",
  "config": "360x800dp/light/fontScale1.0",
  "state": "expanded",
  "nodePath": "lab:preview:sampleButton",
  "rule": "no_overlap_with_fixed_panel",
  "expected": "intersectionArea == 0",
  "actual": "intersectionArea = 0 dp^2",
  "unit": "dp",
  "severity": "P0",
  "status": "pass",
  "skipReason": "",
  "evidence": { "buttonBottomDp": 512.0, "panelTopDp": 520.0 }
}
```

- `status`：`pass` / `fail` / `blocked` / `skip`。
- `blocked`（环境或标签问题）与 `fail`（产品缺陷）严格区分；`skip` 必须写 `skipReason`。
- 报告只含数值与结构化数据，**不含界面截图**。
- 每份报告附覆盖率：已自动测 / 缺标签未测 / 只能人工测。

## 8. 验收分级与通过判定

| 级别 | 内容 | 判定 |
| --- | --- | --- |
| P0 | 裁切、关键元素遮挡、非声明文本溢出、左右 padding 不对称、同组元素不等宽 | 必须为 0 才能验收 |
| P1 | 令牌外取值、同层容器左边距不一致、间距不在令牌集合、基线/中心线偏差超阈值 | 登记并限期处理 |
| P2 | 信息密度、玻璃质感、留白、视觉重心等审美建议 | 人工决定 |

- 通过条件：`P0 = 0` 且无未说明的 `blocked/skip`。
- 白名单必须带理由与复审日期；白名单数量变化写进报告。

## 9. 量化阈值（草案）

| 规则 | 阈值 |
| --- | --- |
| 页面/面板左右 padding 差 | = 0（允许 ≤0.5dp 舍入） |
| 同层容器左边缘 x 差 | ≤0.5dp |
| 同组按钮、底部导航两项宽度差 | = 0 |
| 同行文本 firstBaseline 差 | ≤1dp |
| 图标与伴随文字垂直中心差 | ≤1dp |
| 非声明文本溢出 | 不允许；有意的 `maxLines + Ellipsis` 走白名单 |
| 正文/次要文字对比度 | ≥4.5:1 / ≥3:1（玻璃背景按最不利底色估算，人工复核） |

## 10. 设计令牌（草案，待确认）

- 间距：`4 / 8 / 12 / 16 / 20 / 24 / 32 dp`；`2 / 3 / 5 / 6 / 10 / 14` 是否保留需逐项评审。
- 圆角：组件 `12 / 16`，卡片与弹窗 `24 / 28`，玻璃面板 `32`。
- 页面内容水平 padding：`24`；面板/分组内部：`16`；卡片内边距：`20`（实验室示例卡片当前为 16，需确认是否统一为 20）。
- 组件间距：卡片之间 `16`，组内 `12`，组间 `24`（草案）。
- 按钮高度：`52`（当前出现 2 次），导航手势区 `56`，其余取值需确认。
- 字体：优先 `MaterialTheme.typography`；直接使用 `sp` 的位置必须登记白名单。
